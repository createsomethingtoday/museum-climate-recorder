01 / The contract

Small enough
to inspect.

The C++17 program accepts increasing unsigned 32-bit sequence numbers, reports skipped positions, and rejects duplicate or earlier records as stale. Malformed input preserves the last accepted value.

Two modes share the same sequence checks: interactive mode responds to each line; bulk mode batches I/O for completed exports. The baseline assumes one producer per process and increasing counters within one session.

DATABASE

Keep the evidence.

Raw timings, fixture and artifact hashes, compiler settings, and replay instructions make the observations inspectable.

AUTOMATION

Exercise the real path.

Black-box checks run the recorder as a process. The load experiment uses local pipes and a second recorder importing a file.

JUDGMENT

Bound the claim.

A one-millisecond lab budget exposes misses. A finite guest experiment does not establish a real-time guarantee.

02 / Under contention

The tail tells
another story.

How long does a live producer wait for an acknowledgment while a bulk importer competes for CPU? A pinned ARM64 Linux guest compared idle, shared-CPU, and separate-CPU placement.

The shared-CPU p99 looked comfortable. It concealed both deadline misses.

Around the worst response, the producer accumulated 3.553 ms of runnable wait. That implicates scheduling delay before the producer observed the acknowledgment. The counters cannot identify exactly which task ran, or when the acknowledgment entered the pipe.

03 / Run it

A recorder
you can replay.

The container packages the recorder CLI. Send a short stream through its interactive mode, or use --bulk for a completed export.

printf '7\n10\n10\n' | docker run --rm -i \
  --network none \
  ghcr.io/createsomethingtoday/museum-climate-recorder:v1.0.1

# Completed export
docker run --rm -i --network none \
  ghcr.io/createsomethingtoday/museum-climate-recorder:v1.0.1 \
  --bulk < export.txt > report.txt

The CLI image runs the recorder. The CPU-placement experiment builds from source in a pinned GCC image; follow its separate replay guide. For repeatable releases, use a published digest in place of the mutable latest tag.

04 / Evidence boundaries

What this lab establishes.

Observed and checked

Seven requirement cases passed in each CLI mode. An independent replay also observed 0 / 2 / 0 misses across idle, shared, and separate placement. Raw samples and artifact hashes accompany the experiment.

Still a bench question

This is a synthetic, closed-loop pipe workload in a virtualized guest. Fixed trial order, CPU topology, host activity, and measurement overhead limit generalization. Physical sensor timing, periodic sampling jitter, sustained storage performance, and crash durability require separate experiments.

No physical instrument, PREEMPT_RT qualification, PTP accuracy, or production museum deployment is claimed.
